# AI 在部署环节的建议记录（实验五）

| 类型 | AI 建议原文（摘要） | 我的判断与处置 | 依据 |
|---|---|---|---|
| 有用 | 部署前先执行 `ss -lntp \| grep 8080` 和 `netstat -ano \| findstr :8080` 确认端口占用，再决定是否需要改端口 | 采纳。正是靠这条命令发现宿主 8080 已被本机 Tomcat 占用（PID 19412），VirtualBox 的 8080 端口转发无法绑定，最终改用 8088 转发 | 实际执行后定位到问题根因，改端口后访问返回 200 |
| 不适用 | 直接在本机安装 Docker Desktop，用 `docker run -p 8080:8080 tomcat:9-jdk8` 一条命令部署，不需要 Linux 服务器 | 不采纳。本机没有安装 Docker，也没有启用 WSL2，无法直接运行 Docker；课程要求部署到脱离 IDE 的可访问环境，因此改用 Linux 服务器（JDK8 + Tomcat9 + MySQL8）直接部署 | `docker` 命令不存在，WSL 未安装；服务器方案已验证可访问 |
| 不适用（安全） | 在 Dockerfile 中用 `ENV MYSQL_ROOT_PASSWORD=123456` 固定数据库密码，方便一键启动 | 拒绝。密码写入镜像层会随镜像泄露，且使用 root 账号违反最小权限原则；改为初始化脚本创建 `score_user`，密码通过环境变量覆盖 | 安全性审查结论；数据库账号只授权 class_score 库 |

结论：AI 对排查命令和部署流程的解释有帮助，但环境假设经常与本机不一致，命令必须本人执行验证后再写入文档。
